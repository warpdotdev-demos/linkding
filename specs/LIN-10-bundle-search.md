# LIN-10: Search beyond a bundle
## Summary and approval
[LIN-10](https://warp-se-demo.atlassian.net/browse/LIN-10) preserves bundle-scoped search and adds an explicit way to search outside the bundle. [pkillianjackson approved these recommendations](https://github.com/warpdotdev-demos/linkding/pull/51#pullrequestreview-5701275998) at commit `fc7a8bc39163a9ad2ccce9a7ff37a89987daee20`: “Let's go with your recommendations. Approved.” This PR implements the approved design below.
## Approved behavior
1. **Control:** On the personal Bookmarks page with a valid owned bundle selected, add a secondary **Search all bookmarks** button directly below the input, outside dropdowns. Show it before submission, with zero results, and with invalid queries. Ordinary Search/Enter stays bundle-scoped when no autocomplete suggestion is selected.
2. **Universe and filters:** Submit the live input, including unsent text, to `/bookmarks` without `bundle`. Results contain only the signed-in user's unarchived bookmarks. Remove all saved bundle conditions; retain query tags/operators, effective sort/shared/unread preferences, and explicit added/modified date filters. Do not save preferences. Empty input browses that same universe. Beside the action and on the unscoped page, show **Your unarchived bookmarks; current search filters still apply.**
3. **Destination and return:** Show **In bundle: <name>** beside scoped search, even with a hidden sidebar. Broader results use the normal Bookmarks page, no selected bundle, and **All bookmarks (not archived)** scope text. Back restores the previous scoped URL/results; Forward restores broader results. Restoring unsent edits is not required. Existing sidebar bundle links still reopen the bundle and clear the query. Do not add a return banner or retain the bundle shell.
4. **Lifecycle:** A valid owned `bundle` URL parameter defines scoped search; its absence defines unscoped search. Repeated searches and clearing/submitting empty input retain scope. Reload/copied URLs reproduce scope for the same account/preferences. Pagination, tags, details, and actions retain scope and filters. New searches reset pagination and close details. Do not store scope separately.
5. **Keyboard/mobile:** Use a native `type="button"` button with visible focus, Tab access, and Enter/Space activation. Keep ordinary Enter and autocomplete keyboard behavior unchanged. At 375px viewport width, wrap controls below the input without horizontal scrolling or opening the Filters drawer.
6. **Autocomplete:** Keep broader suggestions unchanged: omit bundle, preserve current suggestion filters, and open bookmark suggestions using the configured target without changing scope. Preserve tag/recent-search completion. In bundle views, add **Bookmark suggestions can come from outside this bundle.**
## Technical design
- Reuse `query_bookmarks` and bundle filtering unchanged (`bookmarks/queries.py:33` and `bookmarks/queries.py:176`). Bundles are saved filters, not membership lists.
- Update `bookmarks/templates/bookmarks/search.html:3`, `bookmarks/templatetags/bookmarks.py:12`, and `bookmarks/styles/bookmark-page.css:48`. Limit the new action/scope text to personal mode; archived/shared pages stay unchanged.
- Add a small search-form `HeadlessElement` wrapper using `bookmarks/frontend/utils/element.js:14`; register it in `bookmarks/frontend/index.js`. The secondary button reads the live input and builds a same-origin GET URL using only `q`, `sort`, `shared`, `unread`, `modified_since`, and `added_since`. Omitted preferences still resolve from the unchanged profile. Drop bundle, user, page, details, return/action parameters, and unknown parameters. Use Turbo history-advance navigation; do not mutate hidden fields.
- Preserve ordinary hidden-field submission (`bookmarks/forms.py:248`), URL propagation (`bookmarks/views/contexts.py:35`), and autocomplete API filtering (`bookmarks/frontend/components/search-autocomplete.js:181`).
## Approved trade-offs and assumptions
- **Button over selector:** one explicit escape action avoids persistent selector state. An empty-state-only link appears too late.
- **Personal active over unified search:** reuses existing access rules; excludes archives/shared collections. Retaining filters avoids surprising resets but requires the explanatory text above.
- **Leave bundle over retain shell:** URL, results, and selection agree. Back/sidebar replace a sticky return control.
- **Preserve over align autocomplete:** avoids expanding this change into suggestion API behavior; the note explains the existing mismatch.
- **Assumption:** users start from saved bundle URLs; no built-in default-bundle preference exists. The requester approved the recommended defaults above.
## Out of scope
Unified archived/shared search; default-view/scope preferences; bundle semantics, search syntax, and suggestion ranking.
